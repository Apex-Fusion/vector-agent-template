# Gotchas

Specific traps this template's own build and mainnet proof run hit, kept here so you don't repeat them.

| Gotcha | What goes wrong | Fix |
|---|---|---|
| **Env contract** | `.env.example` lists four separate identity variables (`SUPPLIER_PRIV_KEY_HEX`, `SUPPLIER_PUB_KEY_HEX`, `SUPPLIER_PKH`, `SUPPLIER_ADDRESS`) from one `gen-keypair` run. Copy only the private key and leave the rest blank, and the agent boots fine but serves an empty public key on `/capability`: buyer-side receipt verification breaks silently, and claims get rejected `wrong_supplier` because the on-chain escrow's supplier hash never matches an empty `SUPPLIER_PKH`. | Map all four printed fields into `.env`, every time you regenerate a key. Don't hand-copy a subset. |
| **Nothing loads `.env` for you outside Compose** | You fill in `.env`, run the agent or a CLI with `pnpm ... exec tsx`, and it fails on a missing variable you can see sitting in the file. The runtime and the CLIs read process environment variables; only `docker-compose.yml` reads the file itself, via `env_file`. | Load it into the shell first: `set -a; . ./.env; set +a` (Git Bash on Windows), once per terminal and again after each edit. Every command in the quickstart inherits it from there. |
| **`docker compose restart` vs. recreate** | You edit `.env` (commonly to paste in `ADVERT_REF` after posting your advert), then run `docker compose restart`. The container comes back with the *old* environment: `restart` reuses the already-created container, it does not re-read `env_file`. | After any `.env` change, recreate instead: `docker compose -f deploy/docker-compose.yml up -d --force-recreate`, or `down` then `up`. |
| **Timeout nesting** | You set `SERVICE_TIMEOUT_MS` close to your advert's `ADVERT_MAX_PROCESSING_MS`, forgetting that a claimed job also spends up to 60 seconds waiting out the Claim confirmation and keeps 30 seconds back to land the Submit. The agent refuses to boot for the `custom` capability rather than let you claim jobs you can't submit in time and forfeit your bond. | Keep `SERVICE_TIMEOUT_MS` at least 60 seconds under `ADVERT_MAX_PROCESSING_MS`. The boot error prints every term and the exact value to lower it to. |
| **Neutral model strings** | The `--model` string you pass to `post-advert` is written on-chain and lands verbatim in every buyer's signed receipt. Naming the upstream vendor or model you're wrapping turns your listing into free advertising for your supply chain and undercuts the point of offering a product under your own name. | Name your product, not your supplier. `records.extract.myproduct.v1` / `my-product-v1`, not the underlying model's own name. |
| **The wire payload is a one-element array, not an object** | The vendored escrow builders hash a canonical one-element message array, `canonicalize([{ content: <text>, role: "user" }])`, as the payload preimage: a buyer can't hand the chain a precomputed hash, only the bytes that produce one. Your `SERVICE_URL` receives that whole array as the POST body, exactly `[{"content":"the quick brown fox","role":"user"}]`. Reach for `JSON.parse(body).content` and you get `undefined`, because the top level is an array. | Parse the array: `JSON.parse(body)[0].content`. The exact bytes are pinned in `try-it/src/buy-once.wire.test.ts`. See the README's "Plug in your software" section. |
| **`127.0.0.1` inside a container is the container** | You run the stack with `docker compose up`, leave `SERVICE_URL=http://127.0.0.1:9091` in `.env`, and every job fails `service_unreachable`. The agent is looking for your service inside its own container, where nothing is listening. The same trap catches a demo service bound to loopback: reachable from your shell, unreachable from the agent's container. | Under compose, address services by name: `SERVICE_URL=http://echo:9091` for the bundled demo, or your own service's compose name. Keep `127.0.0.1:9091` for the local `node examples/echo-service.mjs` path. A containerised service of your own must listen on `0.0.0.0`, not loopback. |
| **Wallet coin selection can spend your own collateral** | Fund a wallet as one lump sum, or let its working balance run thin, and an ordinary transaction's coin selection can consume the UTxO you were counting on as collateral for a later Claim or Accept, with AP3X already locked in an escrow by the time you find out. | Fund every wallet as two UTxOs from the start and keep the working balance clear of the cushion. Full detail and the exact numbers: `docs/WALLET.md`. |

See `docs/LIFECYCLE.md` for timing (deliver-by, the accept window, the Release-path gap) and `docs/WALLET.md` for funding shape and fees.
